**Status:** DRAFT 2026-10-09. Seven owner-decided items from `docs/current/proposals/proposal_journal_digest_followup_decisions.md` (decisions #3, #4, #5, #6, #9, #10 and the deferred ReadFile `lineEndings`/`hasBom` item). Nothing is built yet.

## Problem

Seven independent gaps, all with owner decisions already recorded (that proposal is binding; do not re-ask):

1. **Built-in `Read` on in-repo `.cs` is not blocked.** `.claude/hooks/enforce-dogfood.ps1` denies Edit/Write/MultiEdit/NotebookEdit on `.cs` (block at lines 184-215), Grep (224-274), shell git and shell `.cs` writes, but has no `Read` branch. `.claude/settings.json` PreToolUse matcher is `Edit|Write|MultiEdit|NotebookEdit|Bash|PowerShell|Grep|Agent|Task|.*__ReplaceSnippet|.*__Git` (line 27), so the hook is never even invoked for `Read`. `Test: 'Read .cs (not an edit)'` in `.claude/hooks/enforce-dogfood.Tests.ps1` (line 203) pins `Read` as allowed, but only with an out-of-repo path (`C:\repo\Foo.cs`). CLAUDE.md lines 151-154 say `Read` on a `.cs` "still violates this section even though nothing stops it". Blocking `Read` strands any agent whose frontmatter lists `Read` but no MCP tools. Audit of `.claude/agents/*.md` (frontmatter `tools:`):
   - Need MCP tools added: `failure-root-cause-analyst` (Read, Grep, Glob, Bash, PowerShell; its job is reading tool source), `blocker-writer` (Read, Write, Grep, Glob, Bash; must cite file:line), `design-doc-scribe` (Read, Write, Grep, Glob, Bash; "verify each claim against the code"), `model-eval-log-analyst` (Haiku; Read, Grep, Glob, Bash, PowerShell; log extraction, but logs and fixtures cite `.cs` locations).
   - No C# need, no change: `worktree-diff-sentinel` (git and path checks only).
   - Already have MCP tools: `explore-haiku`, `implementer-advisor`, `journal-improvement-planner`.
   - `tools: "*"` (all tools, MCP included): `implementer`, `implementer-senior`, `orchestrator`, `modeleval-runner`, `planstep-runner`, `test-writer`, `test-writer-senior`.
2. **`scripts/build.ps1` carries a dead HTTP-copy path.** `Invoke-VSCodeServerRestart` (region "VS Code server restart", lines 306-381) is no longer called (its calls at lines 407-414 are commented out; line 402 prints "NOT refreshed"). The `-SkipVSCodeRestart` and `-VSCodePort` parameters (lines 92, 94; `.PARAMETER` docs at 51-63), the header paragraph (lines 13-24) and the `.EXAMPLE` text describe behaviour that does not happen. **Coupling:** `scripts/roslynsentinel-vscode-control.ps1` line 378 calls `build.ps1 ... -VSCodePort $VSCodePort`; removing the parameter without touching that line breaks the control script's `build` verb. The owner wants a separate `scripts/Launch-RoslynSentinelHttpServer.ps1` (mode, tools, port; builds a fresh server into its own directory) instead.
3. **`.roslynsentinel/largeresults` is never cleaned.** Two writers in `RoslynSentinel.Common/LargeResultHelper.cs` (`StoreLargeResultAsync<T>`, `StoreRawJsonAsync`) create `Path.Combine(solutionRoot, ".roslynsentinel", "largeresults")` and name files `largeresult_{yyyyMMdd'T'HHmmss'Z'}_{resultId}.json`. No code deletes them. The folder is shared by concurrent sessions on the same solution.
4. **`ReadFile` does not report line endings or BOM.** Callers cannot tell CRLF from LF before an edit (the EOL guard refuses EOL-changing writes, so a wrong guess costs a turn). `WorkspaceFileEditImpl.ReadFile` (`RoslynSentinel.Tools.Basic/WorkspaceFileEditImpl.cs`, ~lines 300-436) returns anonymous-object success data in five shapes (see Step 15). The only BOM probe, `HasUtf8BomAsync` in `PersistentWorkspaceManager` (~lines 376-390), is `private static`.
5. **The large-result offload stub has no path base.** `AddLargeResultOffloadFilter` (`RoslynSentinel.Server.Basic/ServiceRegistrationExtensionsBasic.cs`, stub built ~lines 676-690) replaces the response with `{ offloaded, resultId, sizeBytes, itemCount, isError, statusMessage, listSummary, message }`. The `WirePathRelativize` filter runs INSIDE the offload filter (registered after it), so the stub is never given the `solutionRoot` property that `WirePathRewriter` stamps on normal responses (`RoslynSentinel.Common/WirePathRewriter.cs`, `SolutionRootKey = "solutionRoot"`). The variable `solutionRoot` already exists in that method (`var solutionRoot = workspaceManager?.GetSolutionRoot();`, ~line 590).
6. **Enum values are case-sensitive in argument validation.** `ToolArgumentValidator.Validate` step 3b (`RoslynSentinel.Server.Basic/ToolArgumentValidator.cs` ~lines 725-749) rejects `framework: "nunit"` with `'nunit' is not a valid value ... Did you mean 'NUnit'?` and burns a turn. Case never changes tool behaviour. The test `Call_WithWrongCaseName_IsRejectedWithClosestSuggestion` (`RoslynSentinel.Tests.Server/TestCategoryToolSchemaTests.cs` line 142) pins the rejection. The repair-and-note machinery already exists for parameter names: `NormalizeParameterCase` (silent rename), `ApplyParameterAliases` and `WrapFlatBatchParameters` (return `IReadOnlyList<string>` notes) and `AppendAliasNotes` in the `AddArgumentValidationFilter` (`ServiceRegistrationExtensionsBasic.cs`, ~lines 970-1040), which appends notes as trailing text blocks on both success and rejection.
7. **CLAUDE.md slice-contract "Out of scope" line** (brief template, lines 76-77) does not say that the implementer must not use Write/Edit/shell writes on `.cs` files; the hook's dispatch warning (`enforce-dogfood.ps1` ~lines 328-329) already suggests that wording.

Design choices (all follow the existing patterns, no new mechanisms):
- **Read block:** a new `Read` branch in `enforce-dogfood.ps1` with the same shape as the Edit/Write branch (`.cs` suffix, `Worktree/` exempt, `Test-PathOutsideRepo` exempt, `Exit-IfBypassed '' $filePath`, then `DenyBypassable`). Bypass routes are unchanged: out-of-repo auto-exempt and the `.claude/bypass.local.json` token with `"tools": ["Read"]`. The deny text names `ReadFile`, `GetFileOutline`, `GetMethodSource`, `Search`, `FindReferences` and the blocking-finding rule. `Read` is added to the settings.json matcher. A guard test fails if an agent that has `Read` but no `*` and no MCP ReadFile tool is not on an explicit no-C# allow-list, so a future agent cannot be stranded.
- **Launcher:** `scripts/Launch-RoslynSentinelHttpServer.ps1`, parameters `-Mode` (default `all`), `-Tools` (maps to `--include-tools=`), `-Port` (default 5100, the server default), `-Solution` (optional, maps to `--solution=`), `-Configuration` (Debug), `-DryRun`. It builds `RoslynSentinel.Server.Advanced\RoslynSentinel.Server.Advanced.csproj` with `dotnet build -c Debug -o <dir> --nologo -v quiet` (same recipe as `scripts/roslynsentinel-mcp-launch.ps1`) into `bin-vscode\http-<port>-<yyyyMMddHHmmss>`. That name deliberately does NOT match the stdio instance pattern `^[0-9a-f]{8}-[0-9a-f]{8}$`, so the stdio sweep and `Get-StdioInstanceFolders` never touch or list it. `bin-vscode/` is gitignored.
- **Sweep:** `LargeResultHelper.SweepExpired(solutionRoot, maxAge, utcNow?)`: non-recursive, only `largeresult_*.json` directly in that folder, by `LastWriteTimeUtc`, per-file `IOException`/`UnauthorizedAccessException` swallowed (a concurrent session may hold a file), returns the deleted count. Called once per server start from a continuation on the startup solution load, because the solution root is only known after the load.
- **ReadFile:** a new public static `FileFormatProbe` in `RoslynSentinel.Common` returns `{ style: "crlf"|"lf"|"mixed"|"none", crlf, lf, cr }` for a string and a BOM check for a path. Response fields added: `lineEndings` (object) and `hasBom` (bool, null when the file is not on disk). Additive only; no existing field changes.
- **Enum repair:** a new `ToolArgumentValidator.NormalizeEnumCase(server, toolName, arguments)` returning notes like the existing repair methods. It repairs only when the value is not an exact ordinal member and exactly ONE member matches under `OrdinalIgnoreCase`; zero or two-plus matches fall through unchanged to `Validate` (still rejects, still suggests). The note is `Note: '{value}' is not a valid value for parameter '{param}' of {tool}; it was treated as '{member}' ('{value}' -> '{member}'). Use '{member}' in future calls.`

## Risks and open decisions

Decisions for the owner:
1. **model-eval-log-analyst tools (Step 2).** Default in this plan: add a minimal read-only set (`ReadFile`, `GetFileOutline`, `GetMethodSource`, `Search`) so a blocked `Read` on a cited `.cs` fixture never strands it. Tradeoff: this Haiku agent is meant to extract from logs and hand the "why" to another agent; giving it source-reading tools may tempt it to analyse instead of extract. The alternative is to leave its tools unchanged and put it on the guard test's allow-list (cost: it cannot read C# at all once Step 3 lands, which the brief names as a likely need).
2. **Control-script HTTP verbs.** `roslynsentinel-vscode-control.ps1` start/restart/status/stopallhttp still manage a `bin-vscode\Advanced.Http` copy (line 80 `$httpOutDir`, default port 5150) that nothing refreshes now. Keep (cost: a stale binary gets started with "restart"), or retire those verbs in a follow-up now that the launcher exists (cost: another script change and doc updates). This plan keeps them and only removes the dead build coupling.
3. **Sweep hook point.** Default: a continuation on the startup solution load in both `WarmupAndAutoLoad*` methods. Gap: a server started without `--solution` never sweeps until that restart pattern changes (the stdio launcher passes `--solution` only when the cwd is inside the repo). Alternative: sweep inside `PersistentWorkspaceManager.LoadSolutionAsync` (Common, lines ~437/444) so any load triggers it, at the cost of sweeping on every manual `LoadSolution` and one more file in the blast radius. Decision #10 says "at server startup", so the default follows it.
4. **`hasBom` for files not on disk.** Default `null` (omitted meaning: unknown) rather than `false`, to avoid a silent wrong answer for in-memory documents. Alternative: always a bool, `false` when unknown.
5. **`lineEndings` shape.** Default `{ style, crlf, lf, cr }` plus a separate `hasBom`. A flatter `lineEnding: "crlf"` string is smaller for weak models but loses the "mixed" counts the owner asked for.
